# app ディレクトリガイド

`app/` はテーマ内の PHP 実装を置く場所です。
このテーマでは **「外部の人が触る場所は少なく」「WordPress 依存は閉じる」** を優先します。

## まず押さえる全体方針

- `WordPress/` は WordPress 依存コードを集約する場所です
- `Shared/` は案件をまたいで再利用したい共通処理を置く場所です
- `Project/` は案件別の実装を置く場所です
- `Interfaces/` はテーマ全体に効くトップレベルの契約を置く場所です
- `Errors/` は `wp_die()` など終了系エラーの窓口を置く場所です

## ディレクトリごとの役割

- `WordPress/`
  - フック、管理画面、プラグイン連携、WP ラッパー、CSV パッケージなど
  - **WordPress 関数を積極的に使ってよい層**
- `Shared/`
  - Config / Logger / CsvReader / CsvWriter / Runtime など
  - WordPress 以外でも使える形に寄せたい共通部品
- `Project/`
  - 案件ごとの処理を置く唯一の窓口
  - 外部メンバーが主に触る前提なので、内部で細かく分割しすぎない
- `Interfaces/`
  - `boot()` を持つ起動クラスや、エラーハンドラのような共通契約
  - 「何を実装すべきか」をトップレベルで明確にするための場所
- `Errors/`
  - テーマ全体の終了系エラーをラップする層
  - `wp_die()` を直接散らさず、差し替えやすさを優先する

## namespace とディレクトリ名について

このテーマは歴史的経緯で、**ディレクトリ名** と **namespace 名** が 1 対 1 ではありません。
例:

- `app/WordPress/*` の多くは `App\CMS\...` namespace を使います
- `app/Shared/*` は `App\Support\...` namespace を使います
- `app/Project/*` は `App\UseCase\...` namespace を使います

そのため、実装を読むときは「置き場所」と「namespace」の両方を確認してください。
Composer では `classmap` も使い、現在の構成を崩さずに読み込めるようにしています。

## 迷ったときの置き場所

- WP フックや管理画面調整 → `WordPress/`
- 今後も再利用したい処理 → `Shared/`
- この案件でしか使わない処理 → `Project/`
- テーマ全体の共通ルールや契約 → `Interfaces/`
- 終了系エラーの差し替えポイント → `Errors/`
