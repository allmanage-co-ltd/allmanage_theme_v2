# SASSの記載について

## 案件のコーデイング第一担当者以外は`style.scss`は触りません。
制作の大部分を委託しているコーダーさんがメインで触りますので、作業バッティングや誤ってコンパイルしてしまった等の先祖返りリスクを軽減するため、触らない方針としています。

## 第二担当者以降のscss記述場所について
**scssの記述は`include`フォルダにファイルもしくはフォルダを作成して、`include.scss`で集約してください。**

```
│ ==========================================================
│ # 第一担当者はこちらで記載
│
├ style.scss                # 第一担当者以外は触らない
├ foundation/               # 第一担当者以外は触らない
├ layout/                   # 第一担当者以外は触らない
├ object/                   # 第一担当者以外は触らない
│
│ ==========================================================
│ # 第二担当者以降はこちらで記載
│
├ include.scss              # 作成したscssファイルインポート
├ include/
│
│  ├ _allmanage.scss        # 誰のファイルかわかるようにする
│  ├ _gucchi0421.scss       # 屋号やニックネームでもOK
│
│  ├ taniguchi/             # ※フォルダを切って分割を推奨
│  │   ├ _company.scss      #   ↑何に対するscssか明確になるため
│  │   ├ _service.scss
```

これまでは`include.scss`一枚で済んでいましたが、弊社含め3人以上で制作に携わる機会が多くなってきましたので、ファイルもしくはフォルダ分割することにします。

複数人で同時期に作業することが多く、gitの取入れも不完全なため、苦肉の策で人名を使いますが、屋号などでも問題ないです。
